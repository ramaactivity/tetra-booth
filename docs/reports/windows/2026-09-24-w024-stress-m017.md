## 2. Uji pemulihan GPU (M-016/M-017)

Booth dev `--camera simulated` (dengan/tanpa printer PDF), di attract, lalu proses GPU dari `app.getAppMetrics()` (`type === "GPU"`) di-kill `taskkill /F /PID`. `tasklist` memastikan proses sudah tidak ada.

| # | Skrip | `child-process-gone` / log `[gpu]` | Boot ulang |
|---|---|---|---|
| 1 | booth + printer PDF | tidak | tidak (60 s) |
| 2 | tanpa printer, listener debug | **ya**: `[gpu] proses GPU mati (killed), relaunch dijadwalkan…` → `[gpu] relaunch booth…` | **ya, 0,3 s** (`[boot]` kedua 15:52:07.145) |
| 3–4 | booth + printer PDF | tidak | tidak (60 s) |
| 5 | booth + printer PDF, cek PID | tidak; `getAppMetrics()` 1,5 s kemudian masih `GPU:15160` | tidak |
| 6–8 | tanpa printer, listener debug | tidak (`gone: []`, metrics masih menyebut PID lama, `gpu_compositing: enabled`) | tidak |
| 9 | sama, + cek layar | tidak | tidak. **fps 0**, klik "Sentuh untuk Mulai" gagal (timeout 3 s), `page.screenshot` timeout 5 s |

- `chrome://gpucrash` lewat `webContents.loadURL` (2×): PID GPU tidak berubah dan tidak ada event. Dugaan: navigasi ke `chrome://` ditolak booth. Di Mac cara ini berhasil.

**Kesimpulan:** di Windows (Electron 44), kematian proses GPU yang "tidak bersih" sering tidak dilaporkan ke browser process. Akibatnya jendela beku sementara main tetap hidup. `gpu-watch` (berbasis `child-process-gone`) hanya menangkap kasus yang dilaporkan. Run ke-1 W-020 (update driver → macet selamanya) cocok dengan pola ini, walaupun di sana main juga `Not Responding`.

Usul untuk Mac (M-018):
1. **Watchdog frame di main:** renderer mengirim heartbeat dari `requestAnimationFrame` (mis. tiap 2 s lewat IPC). Kalau lebih dari 10 s tidak ada heartbeat (dan bukan sedang print), relaunch (`app.relaunch()` + `app.exit()`; print aman lewat jurnal). Bisa juga dengan `webContents.capturePage()` ber-timeout.
2. **Watchdog di luar main** untuk kasus main ikut macet (run ke-1): mis. Camera Service memantau heartbeat booth dan, bila hilang lebih dari 30 s, membunuh lalu menjalankan ulang `Tetra Booth.exe`. Atau launcher kecil / Task Scheduler.
3. Uji ulang di Windows setelah itu dengan skrip `taskkill` yang sama (reprodusibel 8/9).
