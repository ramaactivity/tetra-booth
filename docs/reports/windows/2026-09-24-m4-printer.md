Alur `PrintCore`:
1. Printer dikonfigurasi dan ada di spooler; kalau tidak → `printer_unavailable`. Status error → `printer_error`.
2. Port `PORTPROMPT:` tanpa `--print-to-file` → `output_file_required`.
3. Gambar harus bisa dibaca dan tepat 1200×1800, kalau tidak → `image_unreadable` / `image_size`. Isi file disalin ke memori supaya file tidak terkunci.
4. Kertas dipilih dari `PrinterSettings.PaperSizes`, lalu `PrintableArea` divalidasi → `paper_mismatch` kalau tidak cocok.
5. `PrintDocument` + `StandardPrintController`, margin 0, `PageUnit=Display`, `TranslateTransform(-HardMargin)`, gambar ke 400×600 (4×6 in).
6. Satu halaman per salinan.

## Contoh output (Print to PDF, `--paper-4r A5`, 3 salinan, lewat WebSocket)

```
> print.submit {jobId:"job-a5", copies:3, paper:"4R"}   (dikirim 2x: idempoten)
< printer.status {status:"ready", paperRemaining:null}
< print.submit {accepted:true}          ×2
< print.status {status:"printing"}
< print.done {jobId:"job-a5"}           2859 ms setelah submit
< print.status {status:"done"}
```

PDF `job-a5.pdf` (56 KB):
- `MediaBox` 0 0 419,52 595,32 (A5) ×3 halaman
- Gambar: satu XObject 1200×1800 DCTDecode (JPEG), dipakai ulang di 3 halaman
- Per halaman: `0.75 0 0 -0.75 0 595.32 cm` × `384 0 0 -576 0 576 cm` → kotak gambar x 0–288 pt, y 163,32–595,32 pt = **288×432 pt menempel di pojok kiri atas**

`2x6x2` tanpa `--paper-2x6x2`: `print.failed {code:"paper_not_supported", message:"2x6x2 butuh nama kertas dari config (--paper-2x6x2)"}` 136 ms setelah submit, tanpa file.

Durasi test integrasi: cetak A5 ±2 s per job; kasus gagal 3–200 ms.

## Keputusan teknis (dicatat di DECISIONS #30)

1. **`--print-to-file <dir>`** (di luar desain): tanpa ini, "Microsoft Print to PDF" (port `PORTPROMPT:`) membuka dialog Save As dan memblokir worker print selamanya. Sekarang printer ber-port `PORTPROMPT:` tanpa opsi ini ditolak `output_file_required`. Dibutuhkan juga untuk stress test M8.
2. **Salinan = halaman** dalam satu job spooler, bukan `PrinterSettings.Copies`, karena Print to PDF `MaximumCopies=1` dan kriteria uji meminta jumlah halaman = copies. Untuk DNP perlu dicek di Fase 1b apakah copies driver lebih cepat.
3. **`print.done` = job selesai diserahkan ke spooler**, belum berarti kertas keluar. Memantau job spooler sampai selesai (EnumJobs) menyusul bersama DNP. Target "foto terakhir → print keluar ≤ 20 s" belum bisa diukur.
4. **Status spooler lewat winspool P/Invoke**, bukan `System.Management`: lebih cepat dan tanpa paket tambahan. `paperRemaining` selalu `null` (spooler tidak tahu sisa kertas; counter kertas DNP butuh SDK/driver DNP).
5. **Toleransi `PrintableArea`**: boleh kurang 0,02 in atau lebih 0,25 in dari kertas (overscan borderless). Letter untuk 4×6 ditolak. Angka lebih ini tebakan awal; kalibrasi dengan driver DNP di Fase 1b.
6. **Nama config tidak ditemukan**: untuk 4R lanjut ke pencocokan ukuran (sesuai urutan desain), untuk 2x6x2 gagal. Pesan error menyebut nama config yang tidak ada.
7. Kertas yang di driver didefinisikan melebar (600×400) → gambar diputar 90°, tetap tepat 4×6 in. Belum teruji dengan driver nyata.

## Untuk Mac / booth

- Electron main perlu meneruskan `--printer`, `--paper-4r`, `--paper-2x6x2` saat spawn (M3), dan `--print-to-file` hanya untuk uji/stress.
- Kode error baru yang perlu dipetakan ke UI/log booth: `no_printer`, `printer_unavailable`, `printer_error`, `output_file_required`, `paper_not_supported`, `paper_mismatch`, `bad_paper`, `image_unreadable`, `image_size`, `unknown_job`, `print_error`, `bad_payload`.
- Gambar yang dikirim ke `print.submit` harus 1200×1800 (termasuk 2x6x2 yang sudah digandakan template engine).
