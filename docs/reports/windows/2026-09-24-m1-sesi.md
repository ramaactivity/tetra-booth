# Laporan Windows: verifikasi M1 alur sesi (W-011)

Tanggal: 2026-09-24 · Mesin: HP EliteBook 830 G9 (layar 1920×1200, scaling 150%, tanpa touchscreen), HP 5MP Camera · Basis: `main` @ `1c0f244` di-merge ke `win` (+ W-009 printer)

Cara uji: `pnpm install --frozen-lockfile` (42 s), `pnpm --filter booth build`, Camera Service `dotnet run`. Booth: `electron.exe apps\booth\out\main\index.js --data=$W\data --shots=$W\shots\<uji> --enable-logging` + flag per uji. Skrip bantu sementara di `$W\scratch` (tidak di-commit). Setelah laporan ini, `$W\data` dan `$W\shots` sudah dihapus.

## Ringkasan

| Uji | Hasil |
|---|---|
| 1. Simulasi landscape | **Lulus.** Satu siklus penuh 25 s, output benar, layar sesuai 08-DESIGN |
| 2. Simulasi portrait 450×800 | **Lulus.** Semua konten muat, tidak terpotong |
| 3. Webcam | **Lulus.** Live view di-mirror, strip tidak di-mirror. Raw 1920×1080, capture → preview 0,4–1,3 s, compose 115 ms |
| 4. Kamera diblokir | **Lulus.** `camera_error` "Sebentar ya, kamera lagi disiapkan", pulih ±3,6 s setelah kamera bebas, sesi selesai normal |
| 5. Print | **Lulus.** Satu sesi → PDF A5 lewat `WindowsPrinterAdapter` tanpa dialog, gambar 1200×1800 tepat 288×432 pt di origin. Health booth: `printer ready` |

Tidak ada bug yang kuperbaiki di `booth-core`/`apps/booth`. Temuan dicatat di bawah dan di HANDOFF "Untuk Mac" (M-007).

## 1. Simulasi landscape (`--camera=simulated --demo`)

Urutan fase (log main `[phase]`):
attract → countdown → capture → preview (×3) → review → compose → print_select → printing → qr → attract.
Siklus penuh 25 s. `[session] compose 189 ms`.

| File di `$W\data\sessions\<id>` | Ukuran |
|---|---|
| `raw/1.jpg`, `raw/2.jpg`, `raw/3.jpg` | 3000×2000 (53–55 KB) |
| `out/strip.jpg` | 1200×1800 (78 KB) |

Screenshot (`capturePage`, 1900×1025 px):
- **review** "Cek fotonya dulu": 3 kartu dengan tombol ULANG dan tombol LANJUT merah.
- **print_select** "Mau cetak berapa?": preview strip 2x6x2 (dua kolom identik, "Tetra Booth · 24 September 2026"), tombol −/+ (− nonaktif di 1), CETAK.
- **qr** "Scan untuk simpan fotomu": QR dan tombol SELESAI.

Sesuai 08-DESIGN: latar krem, aksen merah, sans, tanpa gradient, emoji, atau shadow tebal.

Catatan kecil:
- Di review, badge nomor (1/2/3) menimpa label "Foto N" yang tercetak di gambar simulasi. Ini hanya terjadi pada gambar simulasi.
- Angka jumlah cetak "1" di print_select tampak memakai glyph berbeda (angka 1 berkaki). Mungkin font/figure style yang berbeda dari teks lain; perlu dicek di 08-DESIGN.

## 2. Simulasi portrait (`--size=450x800`)

Siklus penuh 25 s, compose 303 ms. Screenshot 654×1073 px. attract, countdown, review, print_select, dan qr semuanya muat tanpa terpotong. Catatan UX:
- Attract: teks tombol "SENTUH UNTUK MULAI" terbungkus dua baris, dan judul rata kiri (landscape rata tengah).
- Review: 3 kartu berjajar horizontal, jadi thumbnail sangat kecil (±90 px lebar) dan setengah bawah layar kosong. Di portrait, susunan vertikal/grid mungkin lebih baik.
- Print_select: tombol CETAK pas di tepi bawah, tanpa ruang tersisa.

## 3. Webcam (`--camera=webcam --demo`)

- Siklus penuh 27 s, compose **115 ms**.
- `raw/1..3.jpg` **1920×1080** (413–476 KB). Stream booth diminta 1920×1080, jadi max 2560×1920 dari W-010 tidak terpakai. `strip.jpg` 1200×1800.
- Jeda capture → preview, dari waktu tulis screenshot fase (keduanya +700 ms setelah fase): **1024 / 433 / 1259 ms** (target ≤ 2 s). File raw tertulis 0,16–0,81 s setelah fase capture mulai.
- **Mirror**, dicek numerik tanpa membuka foto (korelasi thumbnail abu-abu 48×32 terhadap foto asli dan versi dibalik):

| Pasangan | Korelasi, orientasi sama | Korelasi, dibalik | Kesimpulan |
|---|---|---|---|
| countdown foto 2 vs `raw/2.jpg` | 0,492 | **0,842** | live view **di-mirror** |
| countdown foto 3 vs `raw/3.jpg` | 0,521 | **0,855** | live view **di-mirror** |
| slot strip foto 1 vs `raw/1.jpg` | **0,702** | 0,434 | strip **tidak** di-mirror |
| slot strip foto 2 vs `raw/2.jpg` | **0,903** | 0,476 | strip **tidak** di-mirror |
| preview foto 1 vs `raw/1.jpg` | 0,211 | 0,099 | preview tampaknya tidak di-mirror (sinyal lemah) |

- Countdown foto 1 berkorelasi ≈0 ke kedua arah. Screenshot diambil 700 ms setelah countdown pertama mulai, dan live view kemungkinan belum tampil karena `getUserMedia` cold butuh ±1,5 s (W-010). Countdown tetap 3 s, jadi live view sudah muncul sebelum foto.
- Preview tidak di-mirror padahal live view di-mirror, jadi tamu melihat dirinya "terbalik" sesaat setelah capture. Ini umum di photobooth, tapi perlu diputuskan (M-007).

## 4. Kamera diblokir (tanpa admin)

Aplikasi Electron sementara menahan webcam selama 20 s (Windows 11 21H2 memakai kamera eksklusif), lalu booth `--camera=webcam --demo` dijalankan.

```
[phase] countdown        → [liveview] gagal mulai [object DOMException]
[phase] capture          → [session] capture gagal ×2
[phase] camera_error     → [session] reconnect gagal ×5 (tiap 2 s)
(penahan melepas kamera 15:20:40,26)
[phase] countdown        → ±15:20:43,9, sesi lanjut sampai qr → attract
```

- Layar `camera_error`: "Sebentar ya, kamera lagi disiapkan", teks tengah, tanpa elemen lain.
- Pulih ±3,6 s setelah kamera bebas (jeda reconnect 2 s + buka stream).
- Foto 1 diulang dari countdown setelah pulih. Sesi tidak hilang (sessionId sama).
- **Log error tidak berguna:** `[object DOMException]`. Nama dan pesan error (mis. `NotReadableError`) hilang. Saran: log `${e.name}: ${e.message}` (M-007).

## 5. Print (Camera Service dengan W-009)

Camera Service: `--printer "Microsoft Print to PDF" --paper-2x6x2 A5 --print-to-file <dir>`. Booth `--camera=simulated --demo`.

- `[boot] camera service: OK · printer ready`.
- Sesi → `printing` → `qr` normal. PDF `<sessionId>.pdf` (72 KB) tertulis ±2 s setelah fase printing, **tanpa dialog**.
- PDF: MediaBox A5 (419,52×595,32 pt), satu halaman, satu gambar 1200×1800 DCTDecode di `384×576` unit × 0,75 = **288×432 pt di pojok kiri atas**.
- Tanpa printer (uji 1–4, Camera Service tanpa `--printer`): `print.submit` diterima (`accepted: true`), lalu Camera Service mengirim event `print.failed printer_unavailable`. Log `cetak gagal, sesi tetap lanjut` **tidak muncul** karena booth belum mendengarkan event (koneksi WebSocket per-permintaan, `camera-client.ts`). QR tetap muncul. Lihat M-007.
